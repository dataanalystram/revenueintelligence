## 2. Findings

1. **No system required a new core entity** beyond the v1 candidate's core. Every engagement, value, commercial and
   context concept landed in a module or in the extension layer.
2. The canonical changes the pressure test forced are all **additive** and are part of the candidate:
   - `parent_account_id` (Salesforce, HubSpot, Gainsight);
   - Person–Account affiliation (Salesforce, HubSpot, Gainsight);
   - Opportunity lines (Salesforce, HubSpot);
   - `agreement_ref` on subscription lines (Chargebee, Stripe);
   - the Support case specification (Zendesk, Freshdesk, Salesforce, HubSpot).
3. **Semantic choices that need human confirmation** were found in four places. These are mapping decisions, not model
   gaps:
   - HubSpot Lead object;
   - Gainsight CTA;
   - Staircase score (observation vs signal);
   - Fireflies action items.
4. **Source-specific by design:** payments and invoices (payment-sensitive), raw transcript and email bodies (content
   references only, policy-gated).
5. **Still to be proven** by M9C/M9D before the v1.0 freeze:
   - manifest proof for files;
   - JSON/array representation at scale;
   - arbitrary table → custom object;
   - metric time series volume;
   - rejected-observation observability for files and tables.
