## Mutation proofs

Plan §19: break → the named test fails for that reason → restore → green. M10A1 harness rules: one exact
replacement (or one appended statement for a grant), applied to a clean, committed tree (the harness refuses a dirty
tree), the named tests run, `git checkout` restore verified clean, the same tests re-run green. No mutation was ever
committed to `m10a2-impl`.

**Where they ran.** Every proof ran locally on `1e41f16` (VM15's re-proof on `5ac5c1b`) with the real integration
suites, not reduced copies: Testcontainers was replaced, for the run only and outside git, by an alias that starts a
fresh PostgreSQL 16 cluster per "container" (embedded `@embedded-postgres/linux-arm64` 16.13 binaries, so roles and
databases never leak between containers, as in CI) and a local Redis 8.0. Unit proofs use the normal unit config.
Commands (from `apps/api`): unit `pnpm exec vitest run --config vitest.config.mts <spec> -t "<name>"`; integration the
same with the local-container config and the integration spec. **CI cross-check**: VM3, VM7 and VM17 were also applied
together on a throwaway branch `m10a2-vm-ci` (`1f49c71`, draft PR #4 "DO NOT MERGE — M10A2 mutation proof" into
`integration`, CI does not run on non-`main` pushes): run `38513565702`, integration job failed exactly the three
expected tests with the same messages as locally (V3/V4 forward/rollback: audit length `3` ≠ `4`; V7: "promise resolved
undefined instead of rejecting"; V15 illegal transitions: "promise resolved [] instead of rejecting"); the lint job
failed on the mutation itself (`require-await`, VM3); runtime and docker passed. PR #4 closed unmerged, branch deleted.
